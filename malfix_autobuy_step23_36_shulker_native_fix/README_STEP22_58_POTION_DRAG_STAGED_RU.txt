Step 22.58 — staged potion drag unstack fix

Проблема Step 22.57:
- QUICK_CRAFT LMB drag для зелий отправлялся целиком за один tick: pickup -> start -> add slots -> end.
- На SpookyTime-like сервере это могло приниматься частично: например стак 64 зелий раскладывался только в 3 слота по 16, а оставшиеся 16 оставались на курсоре.
- После этого UnstackController видел non-empty cursor и больше не переходил к следующим стакам.

Что изменено:
1. Potion drag-unstack теперь staged, ближе к ручному зажатию ЛКМ:
   pickup -> QUICK_CRAFT start -> добавление одного слота за маленькую задержку -> QUICK_CRAFT end -> settle -> recovery остатка курсора.

2. Добавлена защита от зависания курсора:
   если после QUICK_CRAFT на курсоре остался остаток стака, он кладётся в безопасный пустой inventory slot, а не блокирует дальнейшее расстакивание.

3. Source slot больше не добавляется в drag первым.
   Сначала выбираются реальные пустые слоты main inventory/hotbar; исходный слот используется только как fallback, если не хватает пустых слотов.

4. Для зелий выбирается самый большой подходящий стак первым.
   Это нужно, чтобы после частичного split маленькие остаточные стаки не обрабатывались раньше следующих полных 64-стаков.

5. Обычное right-click расстакивание остальных предметов не тронуто.

Настройки:
- POTION_DRAG_STEP_DELAY_MS = 70ms
- POTION_DRAG_SETTLE_DELAY_MS = 140ms
- POTION_DRAG_CURSOR_PLACE_RETRIES = 6

Если сервер всё ещё режет add-slot packets, можно увеличить POTION_DRAG_STEP_DELAY_MS до 90-120ms.
